# Phase 2 results: the single-photo editor

**Date:** 2026-10-03 · **Measured on:** Apple M1 Pro (8-core CPU, 14-core GPU, 16 GB), macOS, Google Chrome 154, ONNX Runtime Web 1.30.0 · **Builds on:** [Phase 1](phase-1-results.md)

## Verdict

The Phase 2 criterion in [`implementation.md`](implementation.md):

> A photographer drops a 45 MP JPEG, sees a clear before/after at 100% within the preview target once the model is cached, and exports a file whose EXIF matches the original.

| Part                                  | Result                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Drops a 45 MP JPEG**                | Drop, paste, **Choose photo** or ⌘/Ctrl+O, anywhere on the window. The photo is on screen **1.26 s** after it is chosen (decode 0.8 s).                                                                                                                                                                                                                                    |
| **A clear before/after at 100%**      | **Yes.** It opens at true 100% (one photo pixel per device pixel, any `devicePixelRatio`) on the photo's **noisiest region**, with the divider in the middle of a denoised tile. Measured noise (mean absolute Laplacian of luminance) at 100%: **46.8 → 6.5**.                                                                                                            |
| **Within the preview target, cached** | **Yes, in the borderline band (≤ 3 s).** From choosing the photo: first denoised tile at the divider **1.72–1.74 s**, about 1 MP **2.9–3.0 s**, the whole 1280 × 800 view **4.9–5.2 s** (two runs). That includes decoding and building the GPU session; the model's own time for the first tile is **0.45 s**. A second photo in the same session: first tile **0.61 s**. |
| **Exports a file whose EXIF matches** | **Yes.** All 20 EXIF tags of the camera file — make, model, lens, exposure, GPS, maker note — come back identical apart from `Software`, which says `Hush`; the colour profile is kept byte for byte. Checked on the real model (`e2e:real`) and in CI.                                                                                                                    |

Measured with `pnpm --filter @hush/web e2e:real` on a synthetic 45.4 MP camera JPEG (`tools/fixtures/make_large.py`), 1280 × 800 window. On a Retina window (1440 × 900 at 2×: 2135 × 1604 device pixels of photo), a 45 MP photo shows its first tile at **1.64 s** and fills the view (25 tiles) in **11.3 s**.

Every requirement Phase 2 lists — drop zone at the root, viewer at true 100%, before/after divider, live controls, recipes with export and import, all save methods, model download UX, capability notices, keyboard shortcuts, About with licences, Copy diagnostics, full zh-Hant — is built and tested; see below.

## What was built

```
choose ─▶ decode worker ───▶ pipeline worker ───────────────────────▶ main thread
          decode              preview scheduler ──── tiles ────▶       viewer (WebGL2): original + preview tiles
          noisiest region     region crops ──── original pixels ─▶     adjust shader: the four sliders, live
          overview            export: recipe in place ─▶ encode ─▶      divider · zoom · pan · press-and-hold
                              metadata ─▶ save (download · folder · share)
```

| Piece                         | Where                                                             | What it does                                                                                                                                                                                                                                                                       |
| ----------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Display ↔ stored geometry     | `packages/core/src/view.ts`                                       | Points, rectangles and one affine map between the upright photo and its stored pixels, for all eight EXIF orientations. Pixels are never rotated (§2.6); the view is.                                                                                                              |
| The noisiest region           | `packages/core/src/noise.ts`                                      | Immerkær's noise estimator on luminance and colour difference, per 8 × 8 block, low percentile per cell — texture and edges don't count, clipped areas score zero. The viewer opens there (§5.3).                                                                                  |
| Preview grid and scheduler    | `packages/core/src/preview-grid.ts`, `preview.ts`                 | One feathered tile grid per photo, anchored on that region. Tiles run nearest the divider first, on the side that shows the result; each lands as soon as it's done, blended seamlessly with whatever neighbours are done. Cached (LRU, bounded bytes), so panning back is free.   |
| Export estimate               | `packages/core/src/estimate.ts`                                   | The preview's measured cost per pixel × the pixels the export's tile plan feeds the model, plus encoding: "Export (about 6 min)" before the button is pressed (§2.10).                                                                                                             |
| Decode worker                 | `apps/web/src/worker/decode.worker.ts`                            | Decodes, finds the noisiest region and builds the overview on its own thread, then ends — the model loads meanwhile, and the decoder's memory goes with it.                                                                                                                        |
| Editor API in the worker      | `apps/web/src/worker/pipeline.worker.ts`                          | Open for editing, original pixels by region, the preview stream, and an export that pauses the preview, runs the recipe over the decoded photo in place, and decodes it again in the background. Two opens in a row share one model load.                                          |
| Viewer                        | `apps/web/src/editor/viewer/`                                     | WebGL2 at exact device pixels. The adjust stage is a shader with the export's math; the luminance blur it needs is cached, so a slider drag is one pass over the screen. A Canvas 2D renderer running core's own adjust code takes over without WebGL2.                            |
| Editor                        | `apps/web/src/editor/`                                            | One screen (§5.13): viewer, preset, four sliders, save location, Export; format, quality, suffix, remove location and processing behind **Advanced**. State in a zustand store; one session object drives the worker.                                                              |
| Saving                        | `apps/web/src/lib/save.ts`                                        | Download everywhere; **save to folder** in Chrome and Edge (File System Access, remembered in IndexedDB, never overwrites — `name (2).jpg`); the **share sheet** on touch devices. Every save is confirmed; a failure names the photo, the reason and the fix, and keeps the file. |
| Presets                       | `apps/web/src/lib/presets.ts`                                     | Recipes (§4.5) in localStorage: save, apply, update, rename, delete, export as `.hush-preset.json`, import (several at once; newer or unknown operations refused by name).                                                                                                         |
| About, diagnostics, shortcuts | `apps/web/src/app/Dialogs.tsx`, `apps/web/src/lib/diagnostics.ts` | Version, model, its code, weights and training-data licences, source and notices. **Copy diagnostics**: browser, adapter, §2.10 situation, backend, tiles, timings, error names — no field exists for a file name, metadata or pixels.                                             |
| App shell                     | `apps/web/src/app/App.tsx`, `public/theme.js`                     | The drop zone is still the first paint; the editor loads lazily (prefetched when idle). Light grey theme without a dark flash; an unsupported-browser screen; every string in English and Traditional Chinese.                                                                     |

## Decisions

Made during the phase, each with its reason. None changes the spec's intent.

| Decision                                                                                                                              | Why                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A progressive, tiled preview** of everything on screen, nearest the divider first, instead of one ~1 MP crop.                       | At 0.56 MP/s a whole Retina view takes ~10 s, but the first 512-px tile takes 0.45 s. The comparison is clear as soon as the tile under the divider lands; the rest fills in while the photographer looks. Tiles left of the divider (showing the original) wait until last. |
| **512-px preview tiles**, anchored on the noisiest region; exports keep their own 768-px plan.                                        | Per-pixel cost is flat from 512 up (Phase 0), so the smaller tile shows something twice as soon. Preview and export tiles sit differently: the model's per-tile pooling makes them differ by < 1 level (Phase 1: 45–53 dB), invisible.                                       |
| The sliders are a **shader**, not worker work.                                                                                        | §2.5: "on the preview crop this runs at 60 fps." The shader is checked against core's `adjustImage` in CI (≤ 1 level; the Canvas 2D fallback is exact).                                                                                                                      |
| **On the processor**, the preview covers the tile at the divider only, and says so.                                                   | §2.10: "the preview crop shrinks to about 512 × 512 on CPU so it renders in seconds" (1.7 s here). Panning or moving the divider computes more.                                                                                                                              |
| Fit becomes an **overview** (no comparison) only when it shrinks the photo.                                                           | Noise is invisible at fit. A photo smaller than the window is already whole at 100%, so Fit keeps the comparison there.                                                                                                                                                      |
| **Plain drag pans**; press and hold (0.28 s) shows the original; the divider moves by its handle or line; Space + drag pans anywhere. | Lightroom's hand at 1:1, plus §5.3's press-and-hold. Space for those who think in Photoshop.                                                                                                                                                                                 |
| **Instant** zoom, `\` and every keyboard action; menus open in 160 ms and close at once.                                              | Keyboard actions are repeated too often to wait for (emil-design-eng). A menu exit animation kept the old menu mounted, and reopening it in those milliseconds let its focus return close the new one.                                                                       |
| The photo's size is shown **upright** (a portrait reads 4000 × 6000).                                                                 | How photographers read dimensions. Stored pixels are unchanged.                                                                                                                                                                                                              |
| Exports run **in place**, then the photo is **decoded again** in the background.                                                      | Phase 1's memory rule (a 100 MP photo is held once). The viewer keeps what's on screen meanwhile; panning waits for the decode (~0.8 s at 45 MP).                                                                                                                            |
| Folder saves **never overwrite**; they number the file like downloads do.                                                             | A re-export after another tweak must not destroy the first, and silent replacement is the kind of surprise §5.13 rules out.                                                                                                                                                  |
| The **share sheet** is offered only on touch devices.                                                                                 | §2.8 lists it for phones. Desktop share sheets don't offer "Save to Photos".                                                                                                                                                                                                 |
| **About** reads the manifest itself when no photo has been opened.                                                                    | The model's licences belong in About (§4.3) whether or not the model is loaded; the 4 KB manifest isn't the model, which still never downloads without a photo.                                                                                                              |
| Preview colour: **Display P3** photos draw into a P3 canvas; other profiles draw as sRGB, with a note in the panel.                   | Pixels are decoded without colour conversion (§2.6), so a P3 photo would look dull in an sRGB canvas. Adobe RGB and other profiles need an ICC transform in the shader: still open (below). Exports keep every profile byte for byte.                                        |
| **Copy diagnostics** has no field for a file name, metadata or pixels; errors are listed by name and code.                            | §4.7. Error messages can quote a file name, so they are left out.                                                                                                                                                                                                            |

## Measurements (real model, this machine)

From `pnpm --filter @hush/web e2e:real` (`apps/web/e2e/real/editor.spec.ts`), WebGPU, fp16, a 1280 × 800 window at 1×.

| Check                                                | Result                                                                                                                            |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 45 MP JPEG, model cached: photo on screen            | 1.26 s (decode 0.81 s in the decode worker)                                                                                       |
| … first denoised tile at the divider                 | **1.72–1.74 s** (reading the model 0.09 s, GPU session 0.95–1.04 s, the tile itself 0.45–0.49 s)                                  |
| … about 1 MP around the divider                      | 2.92–3.04 s                                                                                                                       |
| … the whole view (9 tiles)                           | 4.9–5.2 s                                                                                                                         |
| … noise at 100%, mean \|Laplacian\| of luminance     | 46.8 (original) → 6.5 (result)                                                                                                    |
| … export                                             | 91.0–98.5 s, estimated 95.8–102.6 s beforehand (each run measures its own speed) · 9.7 MB · 20 EXIF tags, only `Software` changed |
| A 45 MP photo, 1440 × 900 at 2×                      | first tile 1.64 s, ~1 MP 2.85 s, whole view (25 tiles) 11.3 s; export 89.6 s                                                      |
| A second photo in the same session (2.7 MP)          | first tile 0.61 s                                                                                                                 |
| The photographer's photo (2000 × 1333, `HUSH_PHOTO`) | noise 8.6 → 2.4; export 5.5 s                                                                                                     |
| Processor (WASM, 7 threads), 2.7 MP                  | the tile at the divider in 1.7 s; "Export (about 25 s)"                                                                           |
| Cancel an export partway                             | "Stopped. Nothing was saved."; the photo is decoded again and panning carries on                                                  |

**Where the first 1.7 s goes**, and what moved it. Decoding on the pipeline worker used to hold its thread for ~0.9 s while the model waited: first tile 2.4 s. The decode worker took that off the critical path (reading the model from the Cache API: 942 → 94 ms). What remains is ONNX Runtime building its WebGPU session (~0.95 s), once per page — which is why a second photo shows its first tile in 0.6 s.

**Against §4.6.** The spec's preview row (≤ 1.5 s go, ≤ 3 s borderline) is the model's time for a ~1 MP crop with the session ready. Phase 0 measured 1.8 s for one 1120² tile (borderline). The editor's first 512² tile takes 0.45 s and four of them (~1 MP) about 1.6 s: the same borderline band, the same model speed — [Phase 0's speed question](phase-0-results.md#what-to-decide) is still open, and the preview design means less of it is waited for.

**Phase 1's real-model checks, re-run on this branch, are unchanged**: golden images on WebGPU and the processor, seams 53.2 dB (at most 4 levels), 45 MP in 86.7 s (Phase 1: 86.8 s), a real device loss recovered at 45.2 dB, out-of-memory backoff to 288-px tiles at 43.5 dB, and 102 MP through NAFNet in 179.9 s (Phase 1: 180.6 s) with the same 118 MiB peak float memory.

## How to reproduce

```sh
pnpm install && pnpm test && pnpm e2e                                    # what CI runs
pnpm fetch-models --from tools/models/out                                # the release model (Hugging Face once published)
pnpm --filter @hush/web e2e:real                                         # real model, real GPU, installed Chrome
HUSH_PHOTO=/path/to/photo.jpg pnpm --filter @hush/web e2e:real           # the same checks on a photo of yours
```

The 45 MP test photo is written by `cd tools/fixtures && uv run make_large.py` the first time `e2e:real` runs.
