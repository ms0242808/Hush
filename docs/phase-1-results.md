# Phase 1 results: the pipeline, headless

**Date:** 2026-10-02 · **Measured on:** Apple M1 Pro (8-core CPU, 14-core GPU, 16 GB), macOS, Google Chrome 154, ONNX Runtime Web 1.30.0 · **Builds on:** [Phase 0](phase-0-results.md)

## Verdict

Every Phase 1 criterion in [`implementation.md`](implementation.md) passes.

| Criterion                                                                           | Result                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Golden-image tests pass**                                                         | **Yes.** In CI, every format comes back exactly as the test model made it (lossless outputs bit-exact, lossy within their codec's loss). With the real NAFNet, the browser's tiled output matches an independently tiled CPU reference at **62.2 dB** (WebGPU, fp16) and **104.9 dB** (processor, fp32).                                                                         |
| **No visible seams**                                                                | **Yes.** Unit tests drive per-tile offsets, gradients, the detail blur and out-of-memory subdivision across tile and band boundaries: never more than one level of change per pixel. With the real model, 768-pixel tiles against one tile: **53.2 dB, at most 4 levels apart**; on the golden scene, the difference field is no rougher inside tile overlaps than outside them. |
| **EXIF, orientation and ICC round-trip**                                            | **Yes**, for JPEG, PNG, WebP, HEIC and AVIF, read back by exifr (an independent reader) and by spec-written test parsers: every tag kept apart from `Software`, maker notes byte for byte at their offsets, the Display P3 profile byte for byte, pixels never rotated.                                                                                                          |
| **A 102 MP synthetic photo completes on desktop, float memory bounded by one band** | **Yes.** 11648 × 8736 through NAFNet on WebGPU: **180.6 s denoising (0.56 MP/s), 9.7 s encoding, 200.9 s in all; peak float 118 MiB with 736×736 tiles**. In CI (test model, processor) and in plain Node too.                                                                                                                                                                   |
| **`packages/core` tests pass in plain Node**                                        | **Yes**: 269 tests, no DOM or Node APIs in the package (lint-enforced).                                                                                                                                                                                                                                                                                                          |

## What was built

```
File ─▶ read container ─▶ refuse early? ─▶ decode ─▶ tile ─▶ infer ─▶ band ─▶ adjust ─▶ encode ─▶ metadata ─▶ save
        core                core              codec     core    adapter  core    core      codec      core         adapter
```

| Piece                  | Where                                                         | What it does                                                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PlatformAdapters`     | `packages/core/src/adapters.ts`                               | Codecs, inference, model storage, the app's own files, output, SHA-256, zlib, clock (§4.5). The browser implements them in `apps/web/src/worker/adapters/`.                                                                                                               |
| Formats and metadata   | `packages/core/src/formats.ts`, `metadata/`                   | Sniffs JPEG, PNG, WebP, HEIC, AVIF by content. Reads and writes JPEG segments, PNG chunks, WebP RIFF chunks and HEIF boxes. Edits EXIF in place. Derives EXIF orientation from HEIF `irot`/`imir`. Writes a Display P3 profile for `nclx`-only HEIF. Strips GPS from XMP. |
| Recipes and operations | `packages/core/src/recipe.ts`, `operation.ts`; `packages/ops` | Schema 1 operation lists (§4.5). Parameters are clamped and defaulted; an operation from a newer Hush fails with its name. Denoise is the one `ImageOperation`, with four controls.                                                                                       |
| Adjust stage           | `packages/core/src/adjust.ts`                                 | Strength, luminance, colour and detail (§2.5), streamed per finished row with a two-row delay; can write over the original.                                                                                                                                               |
| Resilient tiling       | `packages/core/src/tiled.ts`                                  | Out of memory: the failing tile is split into half-size, feathered sub-tiles, and the smaller size is kept for the session. Device lost: the session is rebuilt and the tile retried; a second loss also halves the tile. Neither restarts the photo (§2.3).              |
| Models                 | `packages/core/src/model-loader.ts`, `model-runtime.ts`       | Manifest → model → variant (fp16 with `shader-f16`, fp32 otherwise) → storage, or parts downloaded and SHA-256-verified → session through the adapter, with the runtime warming in parallel. Tile ceiling from the device's buffer limits.                                |
| The whole photo        | `packages/core/src/pipeline.ts`                               | `processPhoto`: read → refuse early → decode → recipe in place → encode → metadata → save, with §2.7 stage progress, cancellation, and a `SaveError` that keeps the encoded file.                                                                                         |
| Browser adapters       | `apps/web/src/worker/adapters/`                               | jSquash codecs; libheif-js as its own LGPL file; ONNX Runtime on a `GPUDevice` Hush owns, watched for out-of-memory and loss; Cache API; Compression Streams.                                                                                                             |
| Pipeline check         | `/bench/`                                                     | Runs a chosen photo end to end and shows each stage and a before-and-after metadata table read by exifr. Also exposes `window.__hushPipeline` for scripted checks.                                                                                                        |

## Decisions

Made during the phase, each with its reason. None changes the spec's intent.

| Decision                                                                                                                                                                                                                   | Why                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Detail** restores the original's fine _luminance_ texture relative to the model's output: ΔY′ = (1 − d)·ΔY + d·blur(ΔY), with Δ = denoised − original and a 5-tap binomial blur.                                         | It is §2.5's "add back original − blur(original)", taken so the fine band isn't counted twice: adding the original's high frequencies on top of the model's own would sharpen edges. Luminance only, because colour speckle is the colour slider's job. Defaults leave the model's output unchanged.                                        |
| Export **writes over the decoded photo**, row by row behind the band.                                                                                                                                                      | A 102 MP photo is held once in 8 bits (407 MB), not twice. Previews keep a separate output.                                                                                                                                                                                                                                                 |
| An **in-house metadata reader and writer**, with exifr used only as an independent checker (tests and the pipeline check).                                                                                                 | Re-injecting EXIF needs the raw bytes, and keeping maker notes intact needs edits that never move a byte. exifr parses values; it can't write them back.                                                                                                                                                                                    |
| **AVIF exports as JPEG**, like HEIC (§2.6 names only HEIC).                                                                                                                                                                | Writing AVIF means rewriting ISOBMFF item locations and encoding 45 MP with libaom in WASM (minutes). Photographers deliver JPEG.                                                                                                                                                                                                           |
| **Orientation**: JPEG, PNG, WebP and AVIF pixels stay as stored and keep their tag (AVIF's comes from `irot`/`imir`). HEIC comes out of libheif already upright, so it is saved with orientation 1, in EXIF and XMP alike. | "Never rotate pixels", without the rotate-twice bug §2.6 warns about. libheif-js offers no way to skip its transforms.                                                                                                                                                                                                                      |
| **Remove location** strips GPS from EXIF (its data wiped, not just unlinked) and from XMP (`*:GPS*` properties), and drops extended XMP if it holds any.                                                                   | Off by default (§2.6). IPTC holds place names but no coordinates; it stays.                                                                                                                                                                                                                                                                 |
| **Refused before decoding, with reasons**: CMYK JPEG, PQ/HLG HDR, animated WebP and PNG, photos over the §2.9 device limit.                                                                                                | Each has its own message (what happened, what to do) in English and Traditional Chinese. 16-bit inputs are processed in 8 bits, with a warning.                                                                                                                                                                                             |
| **JPEG**: baseline, optimised Huffman tables, 4:4:4 at quality ≥ 90 up to 61 MP, 4:2:0 above that.                                                                                                                         | MozJPEG keeps whole-image buffers in a WASM heap capped at 2 GiB. At 4:4:4, a noisy photo outgrows it between 91 MP (works) and 102 MP (fails) — measured in Node with the same build. An encoder that still runs out is rebuilt and retried at 4:2:0. It is also rebuilt after any photo over 24 MP, so a batch doesn't carry a 2 GB heap. |
| ONNX Runtime runs on a **`GPUDevice` Hush creates**, with ORT's own features and limits (`shader-f16`, `subgroups`, `timestamp-query`; adapter maxima).                                                                    | Hush can then see out-of-memory errors and loss, and give a recovered session a fresh device. ORT 1.30 registers each external device separately. Speed is unchanged from Phase 0 (below).                                                                                                                                                  |
| **WebGPU tile ceiling 768 px** (was 512), capped by `maxBufferSize`/`maxStorageBufferBindingSize` for the model's widest tensor (`tile.channels` in the manifest).                                                         | 4% faster than 512 on the M1 Pro. 1024 is another 7% faster, but each tile is one GPU job, and Windows resets a GPU that is busy for 2 s. 768 is the top of the spec's 256–768 range. Out-of-memory backoff only ever lowers it.                                                                                                            |
| **WebGPU falls back to the processor** when its session can't be created.                                                                                                                                                  | §2.10's fallback, for drivers that pass detection but fail ONNX Runtime. A failure partway through a photo is recovered on the GPU (above) rather than switched.                                                                                                                                                                            |
| **libheif-js** is served as a separate file under `/codecs/libheif/<version>/` and imported by URL, with its licence beside it.                                                                                            | LGPL replaceability (§9.1). It compiles its WASM synchronously (allowed in workers) and needs no `eval`, so the CSP is unchanged.                                                                                                                                                                                                           |

## Measurements (real model, this machine)

From `pnpm --filter @hush/web e2e:real` (`apps/web/e2e/real/`).

| Check                                   | Result                                                                                               |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Golden, WebGPU fp16, 592-px tiles       | 62.2 dB against the same tiling (at most 1 level); 45.2 dB against one pass                          |
| Golden, processor fp32, 416-px tiles    | 104.9 dB against the same tiling (at most 1 level); 45.0 dB against one pass                         |
| Seams, 1024² crop of 24 MP, 768 ceiling | 53.2 dB, at most 4 levels apart                                                                      |
| 24 MP, WebGPU, warm                     | 46.1 s, 0.52 MP/s, 720-px tiles                                                                      |
| 45 MP, WebGPU, warm                     | 86.8 s, 0.52 MP/s, 752-px tiles                                                                      |
| Device lost (a real `device.destroy()`) | 1 device recovered; 45.2 dB against the reference                                                    |
| Out of memory (injected above 400²)     | 1 backoff(s) to 288-px tiles; 43.5 dB against the reference                                          |
| 102 MP through NAFNet                   | 180.6 s denoising (0.56 MP/s), 9.7 s encoding, 200.9 s in all; peak float 118 MiB with 736×736 tiles |

**Speed is unchanged from Phase 0** at the same tile ceiling. Phase 0 measured 46.2 s (0.52 MP/s) at 24 MP with 768-px tiles; Phase 1 measures 46.1 s (0.52 MP/s) on a device Hush creates. Phase 0's open speed question ("rethink") is still open: see [What to decide](phase-0-results.md#what-to-decide).

**Tiles against one pass.** On the golden scene, tiled output differs from a single whole-image pass by 45 dB. The difference is concentrated in a block of 3-pixel stripes (mean 2.8 levels), elsewhere 1.3 levels mean. Each NAFNet block's global average pool sees only its own tile, so very fine texture renders slightly differently per tile. An independent tiler written from the spec reproduces the same 45.2 dB (768) and 45.0 dB (512), which shows the browser pipeline adds nothing. The difference field is no rougher inside the overlaps (0.76 levels/pixel across x, 0.84 across y) than outside them (1.06, 0.85): no seam. On Phase 0's smoother scene the same comparison gives 53 dB.

**Encoding.** MozJPEG takes about 15 s for a 45 MP photo at quality 95 and 4:4:4: its default trellis quantisation can't be turned off through jSquash. That is noticeable next to 90 s of denoising, and worth a faster encoder build if batches show it.

## How to reproduce

```sh
pnpm install && pnpm test && pnpm e2e                                  # what CI runs
cd tools/fixtures && uv sync && uv run make_fixtures.py && cd ../..   # rebuild the test photos
cd tools/models && uv run make_golden.py && cd ../..                   # rebuild the golden images (needs the exported model)
pnpm fetch-models --from tools/models/out && pnpm --filter @hush/web e2e:real   # real model, real GPU, installed Chrome
```
